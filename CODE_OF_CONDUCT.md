# Code of conduct

## Our commitment

Seclyst is a security tool, and the people who use it are often working under
pressure on hostile input. The project is committed to a harassment-free
experience for everyone who takes part, regardless of experience level,
background, identity, or the size of their contribution.

This policy follows the spirit of the [Contributor Covenant](https://www.contributor-covenant.org/version/2/1/code_of_conduct/)
and is deliberately shorter. The standard it sets is the same.

## Expected behaviour

- Assume the other person is acting in good faith until they show otherwise.
- Critique the code, the design, or the decision. Never the person.
- Be specific. "This drops the file handle on the error path" helps; "this is
  bad" does not.
- Accept that a maintainer may decline a change. A declined pull request is a
  decision about scope, not a judgement of you.
- Respect that this is a single-maintainer project with limited review time.

## Unacceptable behaviour

- Harassment, intimidation, or sustained disruption in any project space.
- Insults, personal attacks, or dismissive comments about a person's ability.
- Discriminatory language or imagery, including in issue titles, comments, and
  commit messages.
- Publishing someone's private information without explicit permission.
- Posting working exploit code for a vulnerability in this project in a public
  thread instead of reporting it privately. See [SECURITY.md](SECURITY.md).

## Scope

This applies to issues, pull requests, commit messages, code comments, and any
other space where someone is representing the project.

## Reporting

Report a problem to the maintainer through the contact details on the repository
owner's GitHub profile: <https://github.com/EclipseManic>. Include what happened,
where, and who was involved. Reports are handled privately.

## Enforcement

The maintainer will:

1. Read the report and ask for anything that is missing.
2. Decide whether the behaviour breached this policy, and say which part.
3. Respond with a warning, a request to stop, removal of the content, or a ban
   from the project spaces, in proportion to the behaviour.

A maintainer who is the subject of a report should step back from handling it.
